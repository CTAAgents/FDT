> 状态: **可行性讨论** · 暂不列入实施计划

## 1. 核心问题

FDT 当前是**纯期货 CTA 辩论系统**。将其升级为覆盖 **期货 + 股票(A股) + ETF + REITs + 可转债** 的全市场辩论系统，需要在数据层、因子层、Agent 知识层、风险层四个维度做扩展。

关键问题不是"能否做到"（答案是肯定的），而是 **FDT 的哪些组件是期货特定的？哪些是市场通用的？改造的边际成本有多高？**

---

## 2. 现有组件评估：通用 vs 期货特定

### 2.1 通用组件（0 改造成本）

| 组件 | 说明 |
|:-----|:------|
| **LangGraph 编排** | `graph.py` 的状态机、条件边、Checkpointer 与市场类型无关 |
| **六阶段辩论框架** | 多头立论→空头立论→反驳→结辩，适用于任何可做多空的市场 |
| **P4 闫判官裁决** | 裁决逻辑（置信度、推理链、`if_that_reasoning`）市场无关 |
| **P3.5 品藻质检** | Schema 校验 + conditional_required，市场无关 |
| **P6 报告生成** | HTML 模板框架可复用，只需调整数据段 |
| **自进化闭环** | APM-CS 五轴评分 + RHI，市场无关 |
| **Memory 系统** | MemoryManager + VectorMemory + 偏差跟踪，市场无关 |
| **Harness 工程规范** | 文档/契约/测试体系，市场无关 |
| **LLM 适配层** | `llm_adapter.py` / `llm_provider.py`，市场无关 |
| **数据清洗 K 线管线** | OHLC/去重/离群值/复权，市场无关（除期货特定复权算法） |

### 2.2 期货特定组件（需改造或替换）

| 组件 | 期货特定原因 | 改造方案 |
|:-----|:------------|:---------|
| **数据源** `akshare_source.py` | 仅调用 `ak.futures_hist_em()` 等期货函数 | 新增 stock/ETF/REIT/bond 数据源选择器 |
| **期货专项清洗** `cleaning/futures.py` | 交割月过滤、涨跌停封板标记 | 适用于 A 股（涨跌停），REITs 无需交割月逻辑 |
| **合约换月** `dominant_resolver` | 主力合约映射与换月事件 | A 股/ETF/REITs 无需换月；可转债有转股逻辑 |
| **期限结构因子** `factors/term_structure.py` | 期货特有（近远月价差） | A 股/ETF/REITs 无对应概念；可转债有 YTM 曲线 |
| **基差因子** `basis` | 期货特有（现货-期货价差） | 可转债有转股溢价率（类似概念） |
| **多空持仓因子** `factors/holding_sentiment.py` | 期货交易所公布的持仓排名 | A 股有龙虎榜/融资融券数据；ETF 有份额变化 |
| **仓单数据** `warrant` | 期货交割仓库仓单 | 无对应概念 |
| **链证源 Agent** | 产业链分析（铁矿石→螺纹钢等） | A 股有行业产业链；REITs 有不动产产业链 |
| **风控止损逻辑** `_nodes_boundary.py` | 基于 ATR 的止损（期货波动特性） | 股票可用 ATR + 固定百分比；可转债需基于纯债价值 |
| **Agent 规则** `memory/rules/` | data_sources.md / info_portals.md 针对期货 | 需为每个市场类型创建独立的规则集 |

### 2.3 可复用但需扩展的组件

| 组件 | 当前覆盖 | 扩展需求 |
|:-----|:---------|:---------|
| **观澜 Agent** | 技术面分析（通用 K 线技术指标） | 逻辑通用，但需注入市场特定的参数（A 股涨跌停板、ETF 折溢价） |
| **探源 Agent** | 基本面分析（当前仅期货供需/库存） | 扩展为按市场类型加载不同的基本面指标（PE/PB/ROE/股息率/NAV 折溢价） |
| **读心 Agent** | 新闻情绪分析 | 逻辑通用，但新闻搜索词需按市场类型调整 |
| **P2.5 因子层** | 波动率/价差/期限结构/多空持仓 | 按市场类型注册不同因子集，统一通过 `FactorDashboard` 呈现 |
| **数据清洗** `ohlc.py`/`outlier.py` | K 线级清洗 | 对于 A 股需增加除权除息处理（已有复权管线）+ 停牌标记 |
| **风控明 Agent** | 风控审核（red/yellow/green） | 规则集扩展：A 股 T+1/涨跌停、ETF 折溢价阈值、REITs 流动性风控 |

## 3. 按市场类型的改造影响矩阵

| 改造维度 | 股票(A股) | ETF | REITs | 可转债 | 期货(已有) |
|:---------|:---------:|:---:|:-----:|:------:|:---------:|
| **数据接口** | 中 | 低 | 中 | 高 | — |
| **K 线清洗** | 中（除权除息） | 低 | 低 | 中 | — |
| **因子计算** | 中（PE/PB/ROE） | 低（跟踪误差） | 中（NAV/现金流） | 高（转股溢价/YTM） | — |
| **Agent 知识** | 中（财报分析） | 低（指数分析） | 中（不动产分析） | 高（债性/股性分析） | — |
| **风控规则** | 中（T+1/涨跌停） | 低（折溢价） | 中（流动性） | 中（信用风险） | — |
| **辩论框架** | 低 | 低 | 低 | 低 | — |
| **报告模板** | 中（新增财报段） | 低（NAV 段） | 中（估值段） | 高（债性段） | — |
| **记忆/进化** | 低 | 低 | 低 | 低 | — |

**改造难度**：可转债 > 股票 > REITs > ETF

        """返回该市场类型的完整管线配置"""
        ...

## 5. 结合最新 AI 工程理论的技术路线

### 5.1 Mixture-of-Experts (MoE) 路由

当前 FDT 的 12 Agent 是**全激活**模式（每轮辩论所有 Agent 参与）。全市场场景下，按市场类型做 MoE 路由：

| 市场类型 | 必备 Agent | 可选 Agent | 说明 |
|:---------|:-----------|:-----------|:-----|
| 期货 | 链证源 + 探源 + 观澜 + 读心 | — | 现有全量 |
| 股票 | 探源(财报) + 观澜 + 读心 | 链证源(产业链) | 财报 Agent 替代供需 Agent |
| ETF | 观澜 + 读心 | 探源(指数) | 无需链证源 |
| REITs | 探源(不动产) + 观澜 | 读心 | 新增不动产分析 Agent |
| 可转债 | 探源(债性) + 观澜 + 读心 | 新增债性分析 Agent | 需同时理解股性和债性 |

### 5.2 Embedding-Based Instrument Retrieval

全市场场景下品种数量从几千到几万。用 Embedding 替代穷举扫描：

```python
# 现有：10 通道穷举扫描 all_ranked
# 扩展后：Embedding 检索 → 策略扫描（只扫描 Top-K）
1. 将品种 K 线形态 + 基本面快照 Embedding
2. 计算品种间相似度
3. 按市场类型 + 相似度聚类
4. 只对每类 Top-3 代表性品种做深度辩论
```

### 5.3 增量学习 & 跨市场迁移

利用 FDT 已有的 evolution_graph 做跨市场迁移：

- **参数迁移**：期货市场训练的置信度校准曲线，作为股票市场的先验
- **Prompt 迁移**：期货探源的 prompt 模板 → 股票探源 prompt（术语替换）
- **风控阈值迁移**：期货 ATR=2% 止损 → 股票 ATR 或固定百分比止损

### 5.4 Agentic RAG 增强

全市场场景下知识量暴增（每个市场有自己的规则/术语/分析方法），需要 Agentic RAG：

```python
# 辩论前自动检索市场规则
market_rules = await market_knowledge_base.retrieve(
    market_type="stock",
    instrument="600036.SH",
    query="该股票的财报方法论和估值基准"
)
```

## 6. 改造工作量估算

| Phase | 焦点 | 工作量(人·天) | 说明 |
|:------|:-----|:-------------:|:-----|
| **Phase 0** | 品种分类器 + 市场路由 | 3-5 天 | 核心基础设施，不破坏现有系统 |
| **Phase 1** | A 股数据源 + 清洗 + 因子 | 10-15 天 | AKShare 已有大部分数据，主要是管线集成 |
| **Phase 2** | ETF 数据源 + 因子 | 5-7 天 | 结构相对简单 |
| **Phase 3** | 可转债数据源 + 因子 + Agent | 10-15 天 | 最复杂，需要新的Agent知识体系 |
| **Phase 4** | REITs 数据源 + 因子 | 5-7 天 | 依赖不动产公开数据 |
| **Phase 5** | Agent Prompt 改造 + 测试 | 10-15 天 | 每个 Agent 需要市场感知变体 |
| **Phase 6** | 报告模板扩展 | 5-7 天 | 每个市场类型不同的数据展示 |
| **Phase 7** | 端到端测试 + 校准 | 10-15 天 | 每个市场类型跑 Golden Tasks |

**总计**：约 60-90 人·天（3-4 人月），按并行度优化后可压缩到 6-8 周。

## 7. 风险与约束

| 风险 | 等级 | 缓解措施 |
|:-----|:----:|:---------|
| A 股除权除息数据复杂度 | 🟠 | 复用 AKShare 的复权参数，回测时用后复权 |
| 可转债条款差异大 | 🔴 | 先覆盖主流品种（>5亿规模），小品种延后 |
| REITs 市场流动性不足 | 🟠 | 启用流动性过滤，低于阈值不辩论 |
| Agent Prompt 膨胀 | 🟡 | 市场上下文通过 RAG 动态注入，不硬编码在 prompt |
| 测试覆盖不足 | 🟡 | 每个市场类型至少 10 个 Golden Tasks |
| 辩论框架是否适用于固定收益 | 🟠 | 可转债本身兼具股性和债性，天然适合多空辩论；纯债可能不适合（可先排除） |

---

## 8. 结论

**可行，且改造成本可控。** 核心原因是：FDT 的辩论引擎（LangGraph 编排 + 六阶段辩论 + 裁决体系）是**市场无关的**。主要改造集中在数据接入层和 Agent 知识层，不涉及架构范式变更。

推荐优先顺序（按投入产出比）：
1. **ETF** → 最简单（数据维度少，因子少，与期货共享技术分析框架）
2. **A 股** → 次之（AKShare 数据丰富，Agent 知识有成熟方法论）
3. **可转债** → 再次（条款复杂但 AKShare 覆盖较好）
4. **REITs** → 最后（市场规模和流动性可能不足）

> **最终建议**：先做 Phase 0（品种分类器 + 路由），让系统具备"认识新品种"的能力，然后逐个市场类型扩展。不要一次性全市场铺开。
